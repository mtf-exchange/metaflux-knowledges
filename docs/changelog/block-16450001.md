# Activation notice: block 16,450,001 {#activation-notice--block-16450001}

This page records what changed on chain 114514 at block 16,450,001.

:::info
Live since block 16,450,001. Node 0.9.12 swapped in at block 16,450,000 on 2026-09-22, and every rule below turned on one block later. The page records what changed at that boundary, because a client written against the older behavior breaks on the rows below.

`{"type":"account_state","address":"0x…"}` returns the live `height`. Use it to check where the chain is.
:::

Four behaviors move at one height, so the chain gains one boundary, not four. All four are on the [multi-sig](../concepts/multi-sig.md) lane. The rest of the release changes no request, response or rejection that you can see.

The pin is one block above the swap. The outgoing node commits block 16,450,000 and then halts, so that block still ran the old rules. The new rules apply from the first block after it.

## New rejections {#new-rejections}

Each rejection is a commit verdict. It arrives as a [`200` carrying the rejection envelope](../api/rest/exchange.md#commit-time-codes).

| Action | Refusal | Before the height |
|---|---|---|
| [`convert_to_multi_sig_user`](../api/rest/exchange/account.md#convert_to_multi_sig_user) with more than 16 `signers` | `PRECONDITION_FAILED`: `at most 16 signers` | Accepted |
| `convert_to_multi_sig_user` with an address repeated in `signers` | `PRECONDITION_FAILED`: `signers must be distinct` | Accepted. One such roster locks the account for good. See below |
| [`multi_sig`](../api/rest/exchange/account.md#multi_sig) with more than 16 entries in `signatures` | `PRECONDITION_FAILED`: `at most 16 signatures` | Accepted |

The reference always published both roster rules. The chain did not enforce them until this height.

### A repeated signer locked the account {#repeated-signer}

Read this section if you registered a roster before the height. The quorum counts distinct signers, but the chain checked `threshold` against the raw array length. A `[A, A]` roster at `threshold: 2` converted, and then no envelope could ever reach quorum. A converted account refuses every single-sig path, including the re-key that would repair it. That account cannot act again.

The refusal stops such a roster before it commits. It does not repair a roster that committed before the height. Check each roster that you registered. If its distinct addresses number fewer than its `threshold`, that account is locked.

### The limit of 16 {#why-16}

Each entry in `signatures` costs one signature recovery on every validator, so an uncapped list is work that the caller controls. A roster holds at most 16 signers, so no envelope needs more than 16 signatures. Extra entries never raise the distinct count that the quorum reads.

## A `multi_sig` envelope moves one nonce window, not two {#multi-sig-nonce}

| Surface | Before the height | Now |
|---|---|---|
| The envelope's top-level `nonce` | Advanced the POSTING account's window before dispatch, even when the handler then refused the action | Advances no window |
| `params.nonce` | Advanced `user`'s window after the roster quorum verified | Unchanged |
| An envelope that the multi-sig account posts itself, with the two nonces equal | Refused at commit: the outer advance spent the nonce that the handler then checked | Accepted |

Any account may post the envelope, and the roster quorum is its only authority. So the envelope moves only the window of the account that it acts for, `user`.

Checklist:

1. Keep each roster at 16 distinct addresses or fewer.
2. Send at most 16 entries in `signatures`.

## Unchanged {#nothing-else}

No `/exchange` action tag is added or removed. Every EIP-712 type string is unchanged, so a signed action that verified below the height verifies above it.
